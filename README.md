## Как подключить ИИ-сканер

**Важно:** один `index.html` не может безопасно обращаться к Gemini. Нужна серверная функция.

1. Добавьте `index.html` в корень GitHub-репозитория.
2. Добавьте папку `api` с файлом `api/scan.js`.
3. Подключите GitHub-репозиторий к Vercel. GitHub Pages не выполняет `/api/scan`.
4. В Vercel → Project → Settings → Environment Variables добавьте:
   - `GEMINI_API_KEY` — новый ключ Gemini;
   - `APP_ORIGIN` — точный origin приложения, например `https://your-project.vercel.app` (без завершающего `/`).
5. Перезапустите deployment после добавления переменных.
6. Откройте приложение на Vercel и проверьте сканирование JPG/PNG/WEBP.

### Обязательно: отзовите старый Gemini API key

В исходном загруженном HTML был опубликован рабочий ключ Gemini. Удаления ключа из нового файла недостаточно: он уже попал в клиентский исходник. Отзовите его в Google AI Studio / Google Cloud и создайте новый. Новый ключ добавляйте только в переменные окружения Vercel. Не коммитьте `.env` и секреты в GitHub.

## Важные ограничения перед реальным запуском

Эта сборка чинит запуск интерфейса и переносит Gemini-сканирование на сервер. Но исходная система подписок **не является безопасной для коммерческого PRO-доступа** и не должна считаться исправленной только правками HTML:

- `SECRET_KEY_SALT`, алгоритм подписи, мастер-код `1BEZLEMIT`, генератор и проверка промокодов находятся в клиентском коде. Пользователь может изучить/изменить их.
- `proUnlimited`, `proExpiresAt`, `trialUsed` и `usedPromoCodes` хранятся в клиентском состоянии и отправляются из браузера. Нельзя доверять им как подтверждению оплаты.
- `Telegram.WebApp.initDataUnsafe` не является серверной проверкой личности. Для защиты нужно отправлять `Telegram.WebApp.initData` на сервер и проверять подпись с помощью bot token.
- Публичный Supabase publishable key сам по себе не секрет, но таблица `app_states` должна иметь корректную RLS-политику. Нельзя разрешать анонимному клиенту читать/перезаписывать произвольные строки по `telegram_id`.

Перед продажей доступа перенесите выпуск/погашение промокодов и проверку Telegram-пользователя на сервер, храните оплаченные права на сервере, а запись в `app_states` защищайте проверенной сервером идентичностью. Не используйте секреты из старого HTML повторно.
